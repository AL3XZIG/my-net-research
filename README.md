# Независимость и устойчивость связи между децентрализованными сетями

Исследовательский проект о том, как число, размещение и операторская независимость межсетевых шлюзов влияют на доступность связи между независимыми сетями.

> **Статус:** исследовательский каркас. Численные результаты пока не получены. Все графики и выводы должны строиться по фактически выполненным экспериментам, а не заполняться предположительными значениями.

## Исследовательский вопрос

Повышает ли наличие нескольких независимых шлюзов устойчивость связи между сетями и снижает ли зависимость от одного оператора?

## Цель

Оценить влияние количества шлюзов, топологии соединений и концентрации шлюзов у одного оператора на доступность межсетевой связи.

## Гипотезы

1. Увеличение числа независимых шлюзов повышает доступность связи, однако предельный прирост надёжности постепенно уменьшается.
2. Отказ единственного центрального шлюза приводит к более серьёзному нарушению связи, чем отказ одного из нескольких альтернативных шлюзов.
3. Если значительная часть трафика проходит через шлюзы одного оператора, система сохраняет зависимость от этого оператора даже при формально большом количестве шлюзов.

## Структура репозитория

- `research/` — текст исследования: введение, теоретическая часть и заключение.
- `simulation/` — исходный код графовой модели и автоматические тесты.
- `experiments/` — протоколы экспериментов E1–E5.
- `results/` — таблицы, графики и исходные данные.
- `docs/` — методика, ограничения модели и инструкции по воспроизведению.

## Быстрый запуск

Требуется Python 3.10 или новее. В модели используются только стандартные библиотеки Python.

```bash
python -m simulation.src.run_experiments --trials 10000 --seed 42
```

Запуск тестов:

```bash
python -m unittest discover -s simulation/tests -v
```

Команда запуска экспериментов создаёт CSV-файлы в `results/raw-data/`. Графики пока не генерируются автоматически: их следует строить после проверки и анализа полученных данных.

## Важное ограничение

Модель описывает абстрактную связность графа и вероятностные отказы шлюзов/операторов. Она **не эмулирует протоколы Tor, I2P, Session Router или Yggdrasil**, не моделирует криптографию, маршрутизацию пакетов и реальные задержки. Реальные измерения сетей должны проводиться отдельно и описываться как дополнительная эмпирическая часть.

## План работы

1. Подготовить обзор четырёх основных сетей: Tor, I2P, Session Router и Yggdrasil.
2. Зафиксировать определения независимости, шлюза, отказа и доступности.
3. Выполнить эксперименты E1–E5 на графовой модели.
4. Сохранить исходные данные, параметры запусков и код анализа.
5. При наличии технической возможности провести отдельные измерения реальной сети.
6. Сопоставить результаты с гипотезами и явно описать ограничения.

## Воспроизводимость

Каждый эксперимент должен фиксировать параметры модели, число испытаний, seed генератора случайных чисел, версию кода и дату запуска. Неудачные и повторные запуски также следует документировать.
